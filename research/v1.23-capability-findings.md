# BlackList capability research findings

## Android CallScreeningService
Source: https://developer.android.com/develop/connectivity/telecom/dialer-app/screen-calls

- Android's CallScreeningService handles new incoming/outgoing calls that are not in the user's contacts.
- CallResponse supports blocking, rejecting as if the user did, and silencing the call.
- The service can request that a call not be added to the device call log.
- Caller number verification status can be used as a local signal for invalid or potentially spam calls.
- The service path must remain fast and should not perform expensive or privacy-sensitive history scans.

## Google Play sensitive permissions
Source: https://support.google.com/googleplay/android-developer/answer/10208820?hl=en

- SMS and Call Log permissions are restricted and should be requested only for a permitted, critical core functionality.
- Apps using these permissions may need to complete Google's Permissions Declaration Form.
- BlackList must keep Call Log/SMS intake explicitly user-initiated, narrowly scoped, and clearly documented; a separate non-Play build or alternative picker remains an option if policy review rejects the use case.

## Shizuku
Source: https://github.com/RikkaApps/Shizuku

- Shizuku brokers requests to system services through a Binder service started with root or ADB privileges.
- ADB permissions vary by Android version and are limited; apps should check Shizuku availability and permission before requests.
- Hidden API restrictions and Android-version-specific transaction differences make direct hidden API calls fragile.
- Safe integration should be optional, capability-detected, user-visible, and fail closed. It should not claim that Shizuku can universally replace CallScreeningService or carrier/Telecom privileges.

## Initial product implications

- Prioritize official Telecom APIs, default-handler roles, and notification/channel controls before privileged integrations.
- Treat "ring but show nothing" as a bounded capability: silencing the ringtone does not guarantee suppression of system call UI, logs, or missed-call notifications.
- Root/Shizuku should be an optional adapter for explicitly supported, auditable operations rather than a hidden bypass layer.
